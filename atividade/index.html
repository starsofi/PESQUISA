Front-End e Back-End

Seja muito bem-vindo à nossa página de pesquisa sobre Desenvolvimento Web! Este site foi criado com o objetivo de explorar o universo do Back-End — a estrutura escondida que processa os dados, gerencia a segurança e dita as regras de funcionamento dos sistemas na internet. Navegue pelas seções para compreender a diferença entre cliente e servidor, o papel das APIs na comunicação de dados e as principais tecnologias que movem a web por trás das telas.

O que é Front-End?

O Front-End está completamente interligado com a parte gráfica do projeto, onde o usuário interagirá de forma direta. Desse modo, é crucial que o atuador da área se preocupe em manter o visual do projeto, justamente por ser o rosto, vai fazer as pessoas se interessarem ou não. Pessoas que trablham nesse ramo são chamados de Dev Front-End, e a principal diferença entre um Dev Front-End e um Designer gráfico é que o desenvolvedor não tem formação profissional em design, ele faz faz tudo por linha de comando.

O que é Back-End?

O back-end é o motor invisível de um site ou aplicativo, responsável por processar a lógica, garantir a segurança e gerenciar o banco de dados nos servidores. Os profissionais que constroem e mantêm essa estrutura oculta são chamados de desenvolvedores back-end, programadores back-end ou engenheiros de software back-end.

Qual papel cada um designa?

O Front-End designa o papel de criar o layout, os botões e a interatividade visual da página. Já o Back-End assume a responsabilidade de validar logins, salvar cadastros e garantir a segurança das informações.

Como Front-End e Back-End se comunicam?

Eles se comunicam através de requisições e respostas usando APIs. Quando você clica em um botão na tela (Front-End), uma mensagem é enviada ao servidor (Back-End), que processa o pedido e devolve o resultado.

Onde o Back-End é executado?

O Back-End é executado exclusivamente no lado do servidor. Isso significa que ele roda em máquinas remotas ou serviços de nuvem seguros, e nunca diretamente no navegador do usuário final.

O que é necessário para que ocorra o bom funcionamento do Back-End?

  • Cliente e servidor: O cliente (navegador/app) faz os pedidos e o servidor processa e guarda os dados.
  • Requisição e resposta: É a comunicação entre eles; o cliente pede (requisição) e o servidor devolve o resultado (resposta).
  • HTTP e HTTPS: Os protocolos (regras e caminhos seguros) usados para enviar as informações pela internet.
  • Servidor Web: O software ou máquina que fica ligada 24h recebendo os acessos e gerenciando os arquivos do site.
  • Regras de negócio: A lógica principal do sistema (ex: calcular descontos, validar senhas, aprovar pagamentos).
  • Validação de dados: Checagem de segurança para garantir que as informações enviadas pelo usuário estão corretas e seguras.
  • Processamento no servidor: A execução dos códigos nos bastidores que calcula e gera o que o usuário precisa ver.

Explicação do ciclo (da solicitação ao retorno da resposta):

  1. O Clique (Solicitação): O usuário clica em algo no site. O navegador (Cliente) cria um pacote com esse pedido e envia pela internet (Requisição HTTP).
  2. A Chegada: O Servidor Web recebe esse pedido e passa para o código do Back-End.
  3. O Trabalho (Processamento): O Back-End roda as regras de negócio, valida se os dados estão certos e busca o que precisar no banco de dados.
  4. A Volta (Resposta): O Back-End finaliza o cálculo, monta uma resposta (dados ou uma mensagem) e envia de volta ao navegador.
  5. O Resultado: O navegador lê essa resposta e mostra a atualização na tela do usuário.

APIs:O que são e qual sua funcionalidade?

O que é uma API?

Uma API é uma ponte que permite que dois sistemas diferentes conversem entre si. Ela funciona como um intermediário que envia o pedido de um aplicativo para o servidor e traz a resposta de volta.Um exemplo prático é quando você faz login em um site usando o seu botão do Google ou do Facebook. O site não sabe a sua senha; ele apenas usa a API dessas plataformas para confirmar que você é você.

Para que serve?

A API serve para conectar sistemas diferentes, permitindo que eles compartilhem dados e funções prontas com segurança e agilidade. Na prática, ela evita que o desenvolvedor precise recriar ferramentas do zero (como sistemas de pagamento, mapas ou logins sociais) e garante que o Front-End consiga buscar ou salvar informações no Back-End em tempo real.

O que é API REST?

A API REST é um modelo que usa os comandos padrão da própria internet (o protocolo HTTP) para organizar a comunicação entre sistemas de forma simples, leve e padronizada. Ela funciona através de rotas claras e verbos específicos — como GET para buscar um dado, POST para criar, PUT para atualizar e DELETE para apagar —, garantindo que qualquer Front-End consiga conversar perfeitamente com o Back-End.

O que são endpoints?

Endpoints são as URLs ou endereços específicos de uma API onde o Front-End envia os pedidos para acessar, criar ou alterar um dado no servidor. Eles funcionam como os "pontos de encontro" da comunicação; por exemplo, o endereço ://meusite.com é o endpoint usado especificamente para buscar a lista de produtos cadastrados.

Como o Front-End utiliza uma API?

O Front-End utiliza uma API enviando requisições HTTP para os seus endpoints através de funções do JavaScript, como o fetch ou a biblioteca axios. Quando o Front-End faz esse pedido, ele recebe de volta uma resposta do servidor (geralmente em formato JSON, que é um formato de texto leve) e usa esses dados recebidos para atualizar e renderizar as informações dinamicamente na tela do usuário.

Clique abaixo para saber mais sobre os métodos utilizados:

  • O método GET é utilizado para realizar a busca ou leitura de informações já existentes em um servidor.

  • O método POST serve para enviar dados novos ao servidor com o objetivo de cadastrar ou criar um novo registro.

  • O método PUT é utilizado para atualizar ou substituir completamente todas as informações de um registro existente.

  • O método PATCH serve para realizar modificações parciais, alterando apenas campos específicos de um registro.

  • O método DELETE é enviado ao servidor quando o objetivo do sistema é excluir de forma permanente um registro.
