CLIENT-SIDE

O que é Front-End?

O Front-End está completamente interligado com a parte gráfica do projeto, onde o usuário interagirá de forma direta. Desse modo, é crucial que o atuador da área se preocupe em manter o visual do projeto, justamente por ser o rosto, vai fazer as pessoas se interessarem ou não.

Pessoas que trabalham nesse ramo são chamados de Dev Front-End, e a principal diferença entre um Dev Front-End e um Designer gráfico é que o desenvolvedor não tem formação profissional em design, ele faz tudo por linha de comando.

SERVER-SIDE

O que é Back-End?

O back-end é o motor invisível de um site ou aplicativo, responsável por processar a lógica, garantir a segurança e gerenciar o banco de dados nos servidores. Os profissionais que constroem e mantêm essa estrutura oculta são chamados de desenvolvedores back-end, programadores back-end ou engenheiros de software back-end.

Qual a diferença entre eles?

Critério Frontend Backend
O que é? A interface gráfica com o usuário. A estrutura interna de dados.
Onde roda? No navegador do usuário. Em servidores na nuvem.
Tecnologias HTML, CSS, JavaScript. Python, Node.js, PHP, SQL.

Papeis & Execução

Qual papel cada um designa? O Front-End cria o layout, botões e a interatividade visual da página. Já o Back-End assume a responsabilidade de validar logins, salvar cadastros e garantir a segurança das informações.

Como se comunicam? Eles se comunicam através de requisições e respostas usando APIs. Quando você clica em um botão na tela (Front-End), uma mensagem é enviada ao servidor (Back-End), que processa o pedido e devolve o resultado.

Onde é executado? O Back-End é executado exclusivamente no lado do servidor, rodando em máquinas remotas ou serviços de nuvem seguros.

Funcionamento do Back-End

  • Cliente e servidor: O cliente faz os pedidos e o servidor processa/guarda os dados.
  • Requisição e resposta: O cliente pede (requisição) e o servidor devolve o resultado (resposta).
  • HTTP e HTTPS: Protocolos e regras de caminhos seguros para enviar dados.
  • Servidor Web: Máquina ou software ligado 24h recebendo os acessos.
  • Regras de negócio: Lógica principal do sistema (descontos, senhas, pagamentos).
  • Validação de dados: Checagem de segurança para garantir dados corretos.
  • Processamento no servidor: Código rodando nos bastidores.

Explicação do ciclo (da solicitação ao retorno):

  1. O Clique (Solicitação): O usuário clica em algo e o navegador envia uma Requisição HTTP.
  2. A Chegada: O Servidor Web recebe o pedido e passa ao código Back-End.
  3. O Trabalho (Processamento): O Back-End executa a lógica e busca dados no banco.
  4. A Volta (Resposta): O Back-End gera e envia o resultado de volta ao navegador.
  5. O Resultado: O navegador lê a resposta e atualiza a tela.

APIs & Métodos HTTP

O que é uma API? Uma ponte intermediária que envia o pedido de um aplicativo para o servidor e traz a resposta de volta.

Para que serve? Permite conectar sistemas diferentes e compartilhar dados com segurança.

Exemplo de estrutura de dados (JSON):


{
    "status": "sucesso",
    "usuario_id": 102,
    "funcao": "Desenvolvedor"
}

API REST & Endpoints: A API REST utiliza protocolos HTTP e rotas claras (endpoints) para organizar as mensagens.

Métodos HTTP (Clique para saber mais):

  • O método GET é utilizado para realizar a busca ou leitura de informações já existentes em um servidor.

  • O método POST serve para enviar dados novos ao servidor com o objetivo de cadastrar um registro.

  • O método PUT é utilizado para atualizar ou substituir completamente todas as informações de um registro.

  • O método PATCH serve para realizar modificações parciais em campos específicos.

  • O método DELETE é enviado ao servidor para excluir de forma permanente um registro.
